# M4.2.2 — Semantic Status, Synthesis Precedence, and Decision-Trace Correction

## Scope and immutable boundaries

M4.2.2 is a narrowly additive correction to the interactive M4.2 product runtime. It changes no
FDA/CDER scope statement, operational-availability claim, migration rule, official evidence span,
benchmark label or split, Phase 1 or Phase 2 output, presentation snapshot, paper artifact, or
historical M4.2 dossier byte. FDA availability remains `not_operational`; every regulatory rule
remains `expert_validated: false`.

## Reproduced diagnosis

The accepted public-standards package was inspected with the server's configured product profile
and a deterministic structured-abstention double. No paid or live provider call was made. The
server configuration was `llm_mode=live`; the selected profile was `gpt-5.5`, available through
the Responses adapter with `network_required=true`.

For all three leaves the analyzer produced:

- `analysis.model_run.status = abstained`;
- `analysis.model_run.validation_error = null`;
- semantic trace `Semantic inspection abstained; 0 validated findings.`

The product projection then produced:

- `DossierLeafResult.model.status = failed`;
- `DossierLeafResult.model.failure = null`;
- no `run.failures` entries;
- three published results, three human approvals, and zero pipeline failures.

The cause is a product mapping that preserved only `completed` and `not_applicable`; every other
valid analyzer status was rewritten to `failed`. The Responses adapter itself emits `abstained`
only after a provider response completed, strict structured output validated, and the returned
semantic contract explicitly set `abstained=true`. Provider/transport errors and invalid output
raise exceptions instead. The observed records therefore represent valid structured model
abstentions plus a presentation/projection defect, not provider failures.

The same abstention also exposed two synthesis defects. First, generic unresolved precedence
replaced the hard Case A placement decision and mandatory repair. Second, all abstentions used
`HUMAN_VERIFY_STALE_CONTENT`, even though no stale-content finding existed.

## Runtime contract

Model execution statuses are exactly:

- `completed`: provider/fixture interaction completed with valid structured output;
- `abstained`: interaction completed and valid output declined a substantive semantic finding;
- `failed`: provider, transport, validation, graph, synthesis, or persistence execution failed;
- `not_applicable`: the semantic component was deliberately not executed.

The product result records actual execution mode and adapter. Fixture mode identifies the
internal deterministic fixture and never implies a live GPT-5.5 call. Live mode makes GPT-5.5
available only with complete configuration and constructs the Responses adapter. Disabled mode
does not make the live profile available even if credentials are present.

Retryable transport/provider-API failures retain the existing initial attempt plus two retries.
All other failures terminate immediately. A terminal failure is present in `run.failures`,
increments pipeline failures, and has no published decision result.

## Synthesis contract

- **Case A:** an exact approved hard heading mapping always preserves
  `REUSE_WITH_NEW_CONTEXT` and `CREATE_NEW_CONTEXT_GROUP_AND_SUSPEND_LEGACY_CONTENT`. A semantic
  abstention makes human approval mandatory, preserves a bounded uncertainty reason, and marks
  inspection incomplete without claiming semantic clearance.
- **Case B:** exact `manufacturer="all"` with preservation intent and completed clean inspection
  may produce controlled `REUSE_AS_LEGACY_REFERENCE` with the advisory retained. Abstention
  yields `HUMAN_REGULATORY_REVIEW` and `COMPLETE_DOCUMENT_INSPECTION`.
- **Case C:** a supported applicant mismatch or stale-content occurrence yields
  `HUMAN_REGULATORY_REVIEW` and the existing evidence-bounded verification action. Abstention
  yields human review and `COMPLETE_DOCUMENT_INSPECTION` with no model finding. Completed clean
  inspection may permit controlled legacy reference reuse when no deterministic guard blocks it.

## Summary and graph contract

The dossier summary separately reports published analyzed results, human approval requirements,
model abstentions, and pipeline failures. `failed_count` remains an API compatibility field whose
UI label is `Pipeline failures`.

The product graph contract v3 adds `analysis_limitation` as a non-regulatory node. Its bounded properties are
the component, status, reason category, prompt version, and request digest. It never has a review
status, evidence citation, or enforcement mode. `QUALIFIES_DECISION` connects a limitation to a
hard Case A decision; `LEAVES_UNRESOLVED` connects a limitation that causes an eligibility-gated
human-review decision. No `model_finding` is created for abstention. The explanation graph contains
only the active source heading and mapping, rather than all registered Case A mappings.

## Verification

Automated acceptance is network-free. Deterministic doubles cover clean completion, structured
abstention, invalid output, bounded retry exhaustion, and nonretryable failure. The dedicated
M4.2.2 verifier checks schemas, the three clean fixture outcomes, corrected abstention outcomes,
summary counts, active graph paths, execution-mode disclosure, immutable hashes, and governance
flags. The complete M4.2 verifier must also pass twice.
