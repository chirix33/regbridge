# M2 — metadata and semantic vertical slices

Status: implemented for the controlled prospective FDA/CDER demonstration.

## Governance and operational boundary

FDA forward compatibility remains `not_operational` in the registry, API, UI, paper support, and
demonstration. Current-operational mode bypasses every prospective M1/M2 rule and semantic call.
`author-01` source-verified the two new evidence spans and adjudicated the four M2 rules;
`expert_validated` remains `false`.

The manufacturer guidance is a nonbinding recommendation. Therefore `manufacturer="all"` always
retains an advisory rather than becoming a blanket hard failure. Exact preservation can establish
controlled prospective technical eligibility only under the approved M2-B gate. Explicit
normalization creates a new context group and suspends the old one without resubmitting the
unchanged file/document element. Missing intent abstains.

## Implemented production path

1. The v3.2.2 parser preserves raw keyword values, creates normalized comparison values, and
   extracts bounded PDF page text plus URI/internal link annotations.
2. Link destinations are checked deterministically. Controlled relevance is separate author
   fixture metadata; a model-only clean result never verifies a hyperlink.
3. M1 heading rules and M2 metadata/lifecycle rules run through one typed analyzer service.
4. The fixture, disabled, and live OpenAI-compatible adapters share one structured semantic output;
   every finding cites supplied dossier evidence and malformed/uncited output fails closed.
5. Synthesis retains every finding, applies deterministic precedence, maps semantic risk only to
   human review, and persists result/graph JSON transactionally in SQLite.
6. The shared React workspace covers all three archetypes and distinguishes deterministic facts,
   advisory/hard rules, semantic signals, source evidence, dossier evidence, model status,
   uncertainty, repair, graph, and trace.

## Controlled cases and benchmark drafting

- Five Case B packages cover normalization, exact preservation, missing intent, a stable specific
  value, and an out-of-scope product keyword.
- Six Case C packages cover stale heading, stale applicant, irrelevant external link, clean text,
  ambiguity, and an author-verified relevant internal link.
- `data/benchmark/draft-cases.yaml` contains exactly 30 unfrozen drafts: ten per archetype. The
  user-approved canonical Case B record is author-adjudicated; the other 29 remain `candidate`,
  with `split: unassigned`, until M3 freezes labels and partitions.

## Remaining limits

- M2 does not implement the B0/B1/B2 comparison systems or frozen evaluation; those are M3.
- Semantic fixtures are controlled research observations, not expert ground truth.
- The live adapter is opt-in and never changes benchmark reference labels.
- Uploads remain local-only research inputs; authentication and public deployment are out of scope.
