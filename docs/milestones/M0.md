# M0 — Scaffold and contracts

Target dates: August 29–30, 2026. Implemented against the M0 boundary in
`IMPLEMENTATION.md` section 19.

## Acceptance commands

```powershell
.\scripts\setup.ps1
.\scripts\check.ps1
.\scripts\dev.ps1
```

The first command installs pinned dependencies and exports schemas. The second must complete with
no model key and performs all lint, type-check, test, schema-drift, and production-build checks.
The third starts the local fixture-mode API and UI.

## Scientific and product decisions

- M0 source review verifies registry inclusion metadata and immutability, not a regulatory rule.
- The first registered artifact is an official FDA eCTD v4.0 Technical Conformance Guide snapshot.
- Its manifest-level bindingness is `informative` because the document contains mixed normative
  language; future exact evidence spans own their reviewed bindingness.
- Although FDA jointly issues the source for CDER and CBER, this snapshot deliberately registers
  CDER/NDA applicability only. This avoids silent scope expansion.
- The fixture model validates structured output and rejects citations outside the supplied evidence
  packet. Live transport is configuration-only until M2.
- The UI identifies all three planned archetypes but does not imply they are implemented in M0.

### M0 limitations carried forward

- Registry review is not expert adjudication of an executable regulatory rule.
- Only one official FDA source is frozen; M1 must add exact reviewed heading evidence before a
  heading decision can run.
- The UI is intentionally a scope/provenance shell. Parsing, analysis decisions, evidence drawers,
  and graph neighborhoods are not represented as complete.
- Live model transport is deferred to M2; M0 validates the configuration boundary and supplies the
  deterministic fixture implementation only.
