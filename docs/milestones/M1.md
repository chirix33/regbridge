# M1 — unavailable-heading vertical slice

Status: implemented for the controlled prospective FDA/CDER demonstration.

## Operational disclosure

FDA forward compatibility is `not_operational`. M1 is a prospective research scenario, not an
operational submission workflow. The API and UI always expose that status. When the target context
selects `current_operational`, the analyzer bypasses the prospective rule and returns
`HUMAN_REGULATORY_REVIEW` with unresolved operational availability.

`author-01` performed the recorded source verification, operational-status direction, and rule adjudication. No qualified
external regulatory reviewer has validated the work, so `expert_validated` is `false` throughout.

## Implemented production path

1. The parser accepts a cataloged synthetic fixture or bounded ZIP payload.
2. It rejects traversal, absolute paths, normalized duplicates, symbolic links, oversize or
   over-compressed members, missing backbone XML, DTD/entity declarations, unsupported referenced
   file types, and false PDF signatures.
3. Namespace-independent XML parsing extracts legacy leaf identifiers, headings, lifecycle fields,
   references, locators, and SHA-256 digests.
4. The rule engine matches only the three explicit author-adjudicated mappings; fixture identifiers
   never control a decision.
5. The analyzer emits the closed decision vocabulary, exact evidence, minimum repair, uncertainty,
   approval flag, operational status, and deterministic trace.
6. A typed graph neighborhood connects artifact, heading/version facts, evidence, rule, repair, and
   decision, with a text alternative in the UI.

## Approved rule

- Rule: `FDA-CDER-M1-REMOVED-SUBHEADING-001`
- Explicit mapping: `3.2.S.1.1`, `3.2.S.1.2`, `3.2.S.1.3` → `3.2.S.1`
- Decision: `REUSE_WITH_NEW_CONTEXT`
- Severity: `blocking` for retaining the legacy placement
- Repair: `CREATE_NEW_CONTEXT_GROUP_AND_SUSPEND_LEGACY_CONTENT`
- Reuse: reference the existing document identifier; do not resubmit the physical file or document
  element
- Basis: `mechanical_derivation`
- Enforcement: `hard`, controlled prospective demonstration only
- Governance: `author_adjudicated_for_demo`; `expert_validated: false`

No nearest-available-parent inference is implemented. An unlisted heading abstains to
`HUMAN_REGULATORY_REVIEW`.

## Controlled cases

- Three positive variants independently exercise each approved removed heading.
- A clean negative beneath `3.2.S.1` does not trigger the rule.
- An ambiguous `3.2.S.1.4` example abstains instead of inferring a mapping.
- Current-operational mode bypasses the same positive input.
- Hostile-path, symbolic-link, DTD/entity, and false-file-signature tests exercise security bounds.

## Remaining limits

- This is not a production eCTD converter or submission-package generator.
- The parser intentionally supports only the controlled M1 fixture profile.
- M1 does not implement metadata tension or semantic PDF/hyperlink analysis; those remain M2.
- The graph view is an explanatory projection of typed records, not the source of truth.
- There is no regulatory-expert validation or external second-author check.
